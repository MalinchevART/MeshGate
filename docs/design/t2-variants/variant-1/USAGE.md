# Вариант 1 „Статични активи" — ръководство за употреба (фаза T2)

Лого + favicon изцяло като файлове: **нула React компоненти, нула CDN, нула
шрифтови заявки от SVG-тата**. Този вариант не пипа живи файлове — всичко е
тук, в `docs/design/t2-variants/variant-1/`.

## Файлове и къде отиват при прилагане

| Файл от варианта | Дестинация | Роля |
|---|---|---|
| `favicon.svg` | `apps/web/public/favicon.svg` | таб-икона + brand-mark в топбара (24px) |
| `logo-full.svg` | `apps/web/public/logo-full.svg` | пълен lockup само за Login |
| `index-head.html` | фрагмент в `<head>` на `apps/web/index.html` | `<link rel="icon">` + `theme-color` |
| `USAGE.md` | — | този документ |

Vite копира `apps/web/public/` в корена на dist без обработка → пътищата
`/favicon.svg` и `/logo-full.svg` са валидни и в dev, и в build.

## 1. Топбар (`apps/web/src/App.tsx`, редове 116–119)

Замени само глифа `◈`, **задръж живия текст „MeshGate"** — той е и фолбък, и
по-черен рендер на 16px от колкото SVG текст в `<img>`:

```tsx
// СЕГА (App.tsx:116-119)
<div className="brand">
  <span className="brand-mark">◈</span> MeshGate
  <span className="pill">{me.role}</span>
</div>

// СЛЕД
<div className="brand">
  <img src="/favicon.svg" alt="" width="24" height="24" /> MeshGate
  <span className="pill">{me.role}</span>
</div>
```

Защо `favicon.svg`, а не `logo-full.svg`: (а) браузърът тегли favicon-а за
таб-а независимо от нас → преизползването като mark е **0 допълнителни HTTP
заявки**; (б) на 24px wordmark+таглайн в logo-full са нечетими, а символа в
logo-full заема само ~20% от ширината му; (в) файловете са идентични по
символ — визуална консистентност таб/топбар. `alt=""`, защото текстът до
изображението е истинското име. `.brand-mark` CSS правилото (цветът на глифа)
остава неизползвано за топбара — безвредно; не го трием, ползва се в Login
до момента на прилагане (виж т.2).

### Евентуално една добавка в styles.css (по избор)

```css
.brand img { display: block; }   /* маха baseline-празнината под img */
```

## 2. Login (`apps/web/src/App.tsx`, ред 211)

Това е единственото място с достатъчно място и смисъл за пълния lockup:

```tsx
// СЕГА (App.tsx:211)
<h1><span className="brand-mark">◈</span> MeshGate</h1>

// СЛЕД — Вариант А (препоръчан): пълното лого като h1
<h1><img src="/logo-full.svg" alt="MeshGate" width="180" height="44" /></h1>

// СЛЕД — Вариант Б (консервативен): 24px mark + текст, както в топбара
<h1><img src="/favicon.svg" alt="" width="24" height="24" /> MeshGate</h1>
```

* Вариант А: `width="180" height="44"` = 900×220 в мащаб 1:5; изричните
  размери предпазват от layout shift (CLS) в `.login` картата (340px широка).
  Запази `<p className="muted">MQTT Gateway & Management</p>` отдолу — тя е
  функционален подзаглавие, не се дублира с таглайна на логото.
* Вариант Б: ползвай го, ако Arial-рендерът на wordmark-а (виж рискове)
  те дразни спрямо живия текст в топбара.

## 3. index.html

Вмъкни двата реда от `index-head.html` в `<head>` на `apps/web/index.html`
(след `<title>`). Останалото в ресурса е коментар-обяснение, не се копира.

## Рискове и решения

1. **Шрифтове в SVG-като-`<img>` (главният риск).** SVG, рендиран през
   `<img>`, е санитизиран контекст: **не зарежда уеб-шрифтове** — нито
   self-hosted woff2 от `apps/web/public/fonts/`. Wordmark-ът ще ползва
   локално инсталиран IBM Plex Sans, а той обикновено липсва → **Arial**;
   таглайнът пада на системен monospace. Затова `font-family` е
   „IBM Plex Sans, Arial" (не Inter), а не текстовете са с добър fallback.
   Пиксел-перфектно решение е бъдещ вариант с текст→пътища (outlines) или
   inline `<svg>` компонент (там @font-face работи) — това е съзнателният
   компромис на „нула React компоненти".
2. **Двоен HTTP.** favicon.svg се тегли за таб-а независимо → топбар-mark = 0
   допълнителни заявки. logo-full.svg е +1 заявка (~2 KB, само на Login).
3. **Кеш.** Файловете в `public/` нямат content-hash в името (за разлика от
   Vite-нативните assets) → при смяна на логото старата версия може да се
   задържи. Решение: версиониране `?v=2` при промяна, или header
   `Cache-Control` с кратък max-age от deploy/nginx конфига.
4. **Четимост при 24px.** Щрих 12/220 ≈ 5.5% → 1.31px при 24px: достатъчно
   за техно-марка на тъмен фон; възлите (Ø14–20/220 → 1.5–2.2px) четат като
   точки. Вътрешните връзки (щрих 4 → 0.44px) на 24px практически се топят —
   приемливо, те са вторичен детайл, силуетът на двата триъгълника носи
   разпознаването. При 16px (таб) символът пак се разпознава по силуета.
5. **Двубуквен/нулев фолбэк.** Топбарът запазва живия текст „MeshGate" до
   mark-а → при проблем с изображението брендът не изчезва. В Login (вариант
   А) текстът е в `alt="MeshGate"`.
6. **Светли таб-ове.** Без тъмната плоча (#07131F) цианът на светъл таб-фонд
   е с ~1.6:1 контраст и се измива — затова favicon.svg носи собствена плоча
   (виж коментара вътре във файла).

## Проверка след прилагане

1. `npm run dev` в `apps/web` → таб-икона + theme-color в devtools-Rendering.
2. Light+dark тема на браузъра → символът контрастира и в двата.
3. Излогни се → Login картата: лого 180×44, без скачане на layout-а.
4. `npm run build` → `dist/favicon.svg`, `dist/logo-full.svg` съществуват.
