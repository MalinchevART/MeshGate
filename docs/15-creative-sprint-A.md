Методология: търсене → планиране → изпълнение → доклад.. Статус: Фаза 1 ТЪРСЕНЕ — 4 паралелни прегледа (2026-10-23);

## Инвентар на MeshGate — какво ИМА (за синтезиращите прегледи)

**Данни (натрупвани в Postgres, жив поток през WebSocket):**
- Пакети от Meshtastic мрежи: тема, тип (текст/телеметрия/позиция/nodeinfo/
  съседи/routing/traceroute/криптирано), декодирани полета (текст, батерия,
  SNR, RSSI, lat/lng, канал, възел !hex, packet id), произход (local/мост/
  правило), timestamps. Дедупликирани по packet id.
- Топология „кой кого чу" (NeighborInfo с SNR per съсед, обновява се ~мин.);
- Устройства: възли с канал/батерия/трафик/свежест; mute/block за защита;
- Правила за рутиране: изпълнения + trace стъпки + броячи + версии;
- Мъртви букви (deadletter/) с повторно изпращане; журнал на известията;
- Facets: бройки по тип/канал/възел за произволен прозорец.

**Възможности (бектенд, всичко с API):**
- Канал→канал/брокер/HTTP препращане с трансформации (set_fields,
  topic_template), dry-run с пълен trace, retry/backoff/dead-letter;
- Известия: Telegram/имейл/webhook/WhatsApp(CallMeBot), важност
  (info/important/critical), тихи часове, шаблони с променливи, анти-спам;
- Мостове към външни брокери (двупосочно, с echo/дедуп защити);
- Home Assistant MQTT discovery (батерия/SNR/съобщение/канал на възел);
- EMQX брокер с динамични креденшъли + ACL; карта на възли + връзки по SNR;
- Packet Explorer с жив стрийм + фасетна филтрация; визуален канвас за
  правила; бекъпи/инсталатор/меню; RBAC (admin/operator/viewer) + одит.

**Болки/ограничения (честно):**
- Криптирани канали: без PSK виждаме само възел/SNR/RSSI, не съдържание;
- UI функционален, но семпъл (redesign в движение — собственикът работи по
  дизайн-основа с промпта от docs/14 §B1);
- Позиции идват само от некриптирани/декодируеми канали; някои възли са
  без GPS; RF средата се вижда само през докладвани SNR.

## Фаза 1 — резултати от търсенето (4 прегледа)

### Направление B: LoRaWAN/IoT платформи ✅ (TTN/TTI, ChirpStack, Datacake, TagoIO, Blynk, ThingsBoard, Actility ThingPark, AWS IoT LoRaWAN, RAK WisDM)

ТОП патерни за „платформа, наблюдаваща флот радиоустройства":
1. **Триизборен onboarding** — QR код / каталог-модели / ръчно, с Generate на ключове (TTI);
2. **Профил-базов флот** — един Device Profile → хиляди устройства; вендорски профили в репозитори (ChirpStack);
3. **Единен live event stream на всеки обект** — същите events, които хранят интеграциите, се стриймват в UI (TTI/ChirpStack) — zero-config debugging;
4. **Radio-level packet inspector в cloud** — филтрируем capture 10K пакети, декодиране, „какво изпрати мрежата на устройството" (Actility Wireless Logger);
5. **Decoder с live preview** — JavaScript кодек с реалновремев preview срещу реални payload-и + автоматично създаване на полета (Datacake);
6. **Canary/dead-man правило + Duration условия + Geofence** — „аларма, ако устройство МЪЛЧИ > X часа" (Datacake); по-важно от праговете за радиофлот;
7. **Fleet-first drill-down** — обзор → изключения → таблица с виновници → device page; готови dashboard шаблони (RAK WisDM);
8. **Изход през Webhooks+MQTT+персистентен Storage** (catch-up след downtime);
9. **Мулти-тенант + two-tier роли + tag-based access** (ChirpStack/TagoIO/ThingsBoard);
10. **Claiming** — преносимост на собственост на устройство между мрежи без re-provisioning (TTI CAC).

Бонус: alarm lifecycle (active/ack/cleared) + отделен notification layer (ThingsBoard); solution-as-code с git; **AI асистент за заявки към данни/генериране на правила — вече масов патерн** (Datacake/TagoIO/Blynk/ThingsBoard).
Анти-патерни: суши прагове без duration; мониторинг без proactive alerting; dashboard без drill-down до виновник.

### Направление C: Мониторинг/NOC култура ✅ (Grafana, Netdata, Zabbix, Checkmk, Uptime Kuma, Bloomberg, Flightradar24/MarineTraffic)

ТОП елементи за операторска конзола с живи данни:
1. **Глобален статус банер + брояч по тежест** („N критични, M предупреждения") — PagerDuty модел;
2. **Списък с проблеми по тежест** — цвят върху целия ред, cause/symptom свиване, кратко мигане за новите (Zabbix);
3. **4+ състояния с консистентна семантика**: зелено/жълто/червено/**сиво-Unknown (no data е СЪСТОЯНИЕ, не тишина!)** — винаги с икона/текст, не само цвят;
4. **Sparklines в редовете на таблиците** — тренд без клик;
5. **Heat strip / heartbeat bar** — историята на състоянието като цветни клетки до обекта (Uptime Kuma);
6. **Събитийна лента върху самите графики** (annotations/anomaly ribbon — Netdata);
7. **Drill-down с breadcrumbs** — fleet → хост → метрика; първият слой само обобщение;
8. **Broadcast/listen уиджети** — клик на карта/обект рефилтрира целия екран (Zabbix);
9. **Синхронен времеви контрол + индикатор за свежест + явни празни състояния** („awaiting data", *UNKNOWN*, gaps);
10. **Операторска ергономия** — запазени филтър-табове, ack/suppress от реда, kiosk/TV режим, клавиатурна навигация (урокът на Bloomberg: плътността струва само ако действието е по-бързо от мисленето).

Анти-патерни: alarm flood („всичко е червено" → никой не гледа); стакнати графики; прекалено бърз refresh; радикален редизайн (чупи мускулна памет — Bloomberg се променя инкрементално всеки ден!); скрита липса на данни; клъстеризация без density map при нисък зум (flight-radar).

### Направление D: Диви идеи от 7 далечни домейна ✅ (APRS.fi, marine AIS, flight radar, SDR waterfall, игри, HF прогноза, Waze/Ookla)

ТОП диви идеи по „невижданост" (база: meshmap.net / liamcottle map / MeshMonitor / Site Planner = статус кво):
1. **Mesh Waterfall (спектрограма на мрежата)** — матрица възли×време, цвят = SNR/активност; диря = историята на възел; мрежата като ДИШАЩ СПЕКТЪР. Нищо подобно в mesh домейна; SDR хората го четат инстинктивно;
2. **Fog of Coverage с памет** — черно (никога не чувано) / сиво избледняващо (помнено, несвежо) / ярко (live). ЛИПСАТА на данни става визуален продукт + геймификация (нов възел = разкрит терен);
3. **Прогнозна SNR решетка 24 ч × канал** между две точки, научена от собствения история на мрежата (не физика!): „изпрати сега, не в 19:00" — LoRa усеща листа/температура/нощ;
4. **Time-at-cells density map** — къде мрежата ПРЕКАРВА време, не къде са точките сега (AIS алгоритъм; + филтър за невъзможни GPS преходи);
5. **Heard/Gated двойна карта** — „какво чувам директно" vs. „какво реално ОБСЛУЖИХ"; разликата = загубена полезност на relay (не съществува в mesh мониторинга);
6. **Mesh Playback + geofence форензика** — time slider върху цялата мрежа назад във времето; аларма „възел напусна зоната на relay X" = мрежата се е скъсала;
7. **Bounty карта** — графов анализ: къде ЕДИН нов възел би свързал два острова → публикувано като challenge;
8. **Статистически range rings** — „доказан с N измервания обхват" с кофи на достоверност (aprs.fi дисциплина);
9. **Панел „условия на мрежата"** — днес мрежата е +3 dB над седмичната норма (HamQSL-стил метър);
10. **DF-режим „операторна гледка"** — ASCII-плътен ред на възел (hop, SNR тренд стрелка, батерия като bars) на един клик от красивата карта.

Готови техники за преправяне: Supercluster (стабилни клъстери), WebGL rendering (FR24).
Извод: „измерено, не предсказано" + „времето като първокласна ос" + „липсата на данни като визуализация" — комбинаторика, никой не я е сглобил в Meshtastic мониторинга.

### Направление A: Meshtastic екосистема ✅ (Yeraze/MeshMonitor, liamcottle map+meshtxt, meshmap.net, PotatoMesh, OverMesh, ui-ha, Meshpoint, metrics-exporter, coverage map, ATAK, firmware екстри)

Важни находки: liamcottle/meshmonitor Е ИЗТРИТ (наследник = Yeraze); "mesh.galaxy"/"signalmonitor" не съществуват; AtakPlus е микс — реалните са официалните plugins.

ТОП функционалности по рядкост/стойност:
1. **RF coverage heatmap от MQTT наблюдения** — SNR/RSSI → термична карта на покритието на ретранслатор (PaulTimmins/MeshtasticCoverageMap — практически уникално);
2. **Теренен link planner с Fresnel зони + 3D terrain** в самия monitoring UI (Yeraze MeshMonitor: line-of-sight, link budget, auto-честота; MapLibre 3D + DEM);
3. **Федерация между общностни dashboards** — инстанциите се откриват взаимно (PotatoMesh);
4. **Concentrator-граде пълен ефир + identity-preserving smart relay** (Meshpoint SX1302);
5. **MQTT Geo Filtering bounding box с retroactive purge** на данни извън регион (Yeraze);
6. **MAP_REPORT "local online count" + NeighborInfo** — златна мина за плътност/топология БЕЗ изтичане на позиции; firmware я дава, почти никой не я консумира;
7. **SSO/RBAC/audit + Web Push/Apprise + geofence + airtime-cutoff автоматизации** (Yeraze — enterprise патерни в хоби инструмент);
8. **TimescaleDB стек с 5 linked Grafana dashboards + "Investigation" режим** (цветно кодирани SNR/RSSI/hops колони; tcivie exporter);
9. **Standalone ATAK plugin в процеса на ATAK + Lockdown provisioning** (официален pluginmeshtastic);
10. **Интеракционен Cytoscape граф „кой говори с кого"** с time-window (filipsPL — единственият граф-центричен).

Струва си: отделяне ingest/display; „възел като 24/7 gateway"; честна документация на data quirks; onboarding FAQ „как да се появиш на картата" (meshmap.net).

## Фаза 2 — синтез (други прегледи, пресни очи)

### Синтезатор 1: операторна стойност ✅

7 предложения (име → комбинация → рейтинг):
1. **Касова бележка (Delivery Ledger)** — Heard/Gated × packet inspector × сиво-Unknown, върху packet id + origin + дедуп: end-to-end статус на всеки изпратен текст (доставено/качено в MQTT/без следа) — РАБОТИ И ЗА КРИПТИРАНИ КАНАЛИ (метаданно ниво); чип в Packet Explorer + известие при изчезване → **9/10, M, невиждано**;
2. **Изпрати сега (Send-Now решетка)** — прогнозна SNR решетка × метър „спрямо норма" × duration: 24ч×ден статистика на SNR per връзка от нашата история + правило „задръж некритичното до добър прозорец" (dry-run симулация) → 8/10, M, невиждано;
3. **Канарата (научен dead-man)** — canary с НАУЧЕН per-node каденс (p95 inter-arrival) + heat strip + сиво-Unknown: едно известие чак когато възелът мълчи над собствения си ритъм → 8/10, M, частично ново;
4. **Двете уши (чутна асиметрия)** — матрица „кой от моите възли чу този packet id" → автодиагноза „проблемът е възел Б, не ретранслатора"; SNR-ът се вижда и от криптирани → 8/10, S-M, невиждано;
5. **Сутрешен бриф** — тихите часове агрегират; в 08:00 ЕДНО съобщение спрямо седмичната норма („RPT-X мълча 02–05, обичайно за сряда; SNR −4 dB под норма; 2 dead letters") → 8/10, S;
6. **Водопад (Mesh Waterfall)** — спектрограма възли×време, цвят = SNR/активност; трендовете се виждат с периферно зрение → 7/10, M, невиждано;
7. **Досие на възела (Case File)** — единен хронологичен поток per възел (текст+телеметрия+routing+съседи, цветно кодирани колони) + sparklines + breadcrumbs → 7/10, M.

Нишка в топ 4: обръщат НАТЪКАНАТИТЕ метаданни (packet id, origin, SNR, freshness) в отговори на всекидневни въпроси, вместо в още графи.

### Синтезатор 2: невиждани визуализации ✅

7 предложения: **Мрежов водопад** (матрица връзки×време; криптираното — ЩРИХОВКА „известна неизвестност"; 9/10, M) · **Ефир-часовник** (7×24 решетка медианен SNR от собствената история + текстов извод „прати сега"; 8/10, M) · **Мъгла и следи** (fog-of-war + time-at-cells плътност; фантомите без GPS — честно само в топологията; 8/10, M) · **Пулс-ленти** (heartbeat клетки в реда на възела: чист/криптирано-шарка/мълчание-сиво + SNR sparkline; 8/10, **S**) · **Фуния на полезността** (Ефир→Декодируеми→Хванати→Доставени→Deadletter с drill-down — екран, който НИКОЙ конкурент не може да клонира, данните са от rule-engine журнала ни; 8/10, M) · **Лента на аномалиите** (маркери deadletter/известия/версии на правила върху всяка графика; 7/10, **S**) · **Плейбек** (time slider + geofence „възел напусна зоната на relay X"; 7/10, L).

Принципи: „измерено, не предсказано" + „no-data е състояние, не тишина" — криптираните канали и липсващият GPS стават ДИЗАЙН-ЕЛЕМЕНТИ, не ограничения.

### Финална програма (четири вълни, по ред на внедряване)

**Вълна 1 — Бързи победи (цена S, дни; в сегашния UI):**
1. **Пулс-ленти на възлите** — 24ч/7д клетки в реда: чуван чисто / чуван криптирано (лилаво-шарка) / мълчание (сиво, „мълчи X ч" от последната кофа или devices.last_seen) + среден SNR на кофа в tooltip-а. РЕШЕНИЕ по контракта: SNR „sparkline" като ГРАФИКА е съзнателно отложена за таб „Време" (Вълна 3, Водопадът) — плътността на 140 реда × графика е анти-патерн (преглед C); в tooltip текста SNR стойността Е налична. Реализирано през phase-execution (3 подетапа: варианти → детайлни прегледи → QA FAIL с 8 дефекта → поправени → повторен QA).
2. **Лента на аномалии** — маркери (deadletter, изпратено известие, publish на правило, SNR скок) върху всяка графика; клик → trace [S2-6, 7/10];
3. **Сутрешен бриф** — тихите часове агрегират; 08:00 ЕДНО съобщение спрямо седмичната норма [S1-5, 8/10]. РЕШЕНИЕ по контракта: „спрямо седмичната норма" изисква ≥7 дни данни и идва с Ефир-часовника (Вълна 3) — първият срез е честният бриф от последните 24 ч: пакети/възли/нови/канали/тихи фаворити (активни вчера, мълчат >12 ч)/слаби батерии (топ 3 + брой)/мъртви букви; канал с config.digest_hour 0–23 (валидира се) го получава ВЕДНЪЖ дневно — двойният бриф при рестарт е предпазен през журнала, боклучивият час не спира другите канали, TZ=Europe/Sofia; преглед: Известия → ☕ панел + GET /v1/notifications/digest;
4. **Двете уши** — матрица „кой от моите възли чу packet id" → автодиагноза възел vs. среда vs. ретранслатор [S1-4, 8/10, S-частта].

**Вълна 2 — Уникалният монитор (M; отличава ни от всичко):**
5. **Касова бележка (Delivery Ledger)** ★ 9/10 — end-to-end статус на всяко съобщение по packet id (доставено-ACK / качено в MQTT / без следа), чип в Explorer + известие; работи И ЗА КРИПТИРАНИ КАНАЛИ. Бележка за имплементация: Routing ACK пакетите носят request_id — малко разширение на декодера ( Routing.error_reason/request_id ) и JOIN-ът става директен;
6. **Канарата** — научен per-node каденс (p95 inter-arrival) + duration → ЕДНА аларма при истинско мълчание; ползва пулс-лентите [S1-3, 8/10].

**Вълна 3 — Флагмански екрани (M; в НОВИЯ дизайн):**
7. **Таб „Време"** = Мрежов водопад (връзки×време, криптирано-щриховка) + Ефир-часовник (7×24 SNR решетка + „изпрати сега") + лентата на аномалии [S2-1 9/10 + S2-2 8/10];
8. **Таб „Полезност"** = Фунията (Ефир→Декодируеми→Хванати→Доставени→Deadletter, клик-до-trace) — неклонируем екран [S2-5, 8/10].

**Вълна 4 — Карта 2.0 (M/L; последна):**
9. **Мъгла и следи** — fog-of-war + time-at-cells плътност + фантоми [S2-3, 8/10];
10. **Плейбек + geofence форензика** — time slider върху всичко; аларма „възел напусна зоната" [S2-7, 7/10].

Отпаднали при прегледа: „Досие на възела" (7/10 — Вълна 1 пулс-ленти + детайл на карта го покриват на 80%); „Изпрати сега" като отделна функция (слята в Ефир-часовника); „Водопад" в сегашния UI (чака redesign, за да не се прави дваж).

**Принцип на цялата програма: измерено не предсказано; no-data е състояние; метаданните стават отговори.**
