# ADR-002: Deployment — Docker Compose с фиксиранı версии и Traefik v3

- Статус: Прието
- Дата: 2026-10-12

## Контекст

Платформата трябва да се вдига от чиста машина с една команда, да оцелява след
рестарт (именовани томове) и да е подходяща за напреднал домашен потребител или малък
оператор. Работната машина (Windows) няма Node.js; EMQX няма native Windows версия.
Липсва и локален Docker към момента на писане — имплементацията на Фаза 0 започва
след неговата инсталация (решение на собственика).

## Решение

1. **Docker Compose** като единствен deployment механизъм за MVP. Без Kubernetes,
   без допълнителна оркестрация — целевият потребител я няма и не му трябва.
2. **Фиксирани тагове** на всички изображения (`emqx/emqx:5.8.8`, `postgres:16.x`
   конкретен minor, `traefik:v3.x` конкретен, `python:3.13-slim`, `node:22-alpine`
   само за build stage). Никакви `latest`. Точните тагове се потвърждават при първи
   `docker pull` и се записват в `deploy/docker-compose.yml` + `docs/05-deployment-plan.md`.
3. **Traefik v3** (Apache 2.0) като единствен публичен вход: TLS терминация, рутиране
   на web/api/ws, автентикационна граница за административни UI-та. Защо Traefik, а не
   Caddy/Nginx: декларативни labels в compose (конфигурацията живее до сервисите),
   добра WebSocket поддръжка, вграден ACME.
4. **Административните портове не се публикуват** (EMQX 18083, Postgres 5432,
   Node-RED 1880, VictoriaMetrics 8428). Публикуват се само: 80/443 (Traefik) и
   1883/8883 (MQTT listeners).
5. **Healthcheck** за всеки сервис; `depends_on: condition: service_healthy` —
   Core API стартира само след здрави Postgres и EMQX.
6. **Frontend build в Docker multi-stage** (node:22-alpine stage → статика в nginx/
   Traefik обслужване) — host машината не се нуждае от Node.js за деплой; за локална
   frontend разработка е удобно Node на host-а, но не е задължително (възможен е и
   dev контейнер).
7. Именовани томове: `pg_data`, `emqx_data`, `vm_data` (Фаза 2), `nodered_data` (Фаза 4).
   Backup процедурата — в `docs/05-deployment-plan.md` §6.

## Последствия

- (+) Един вход, ясни зони, минимална повърхност за атака.
- (+) Възстановяване/миграция чрез томове + pg_dump, без вътрешно състояние извън тях.
- (−) Локална разработка на backend-a срещу локални процеси е възможна (FastAPI + локален
  Postgres), но EMQX компонентата изисква Docker — приемливо.
- (!) Traefik конфигурацията расте с фазите (Node-RED route и т.н.) — всяко разкриване
  на нов административен UI минава през ADR-проверка на сигурността.
