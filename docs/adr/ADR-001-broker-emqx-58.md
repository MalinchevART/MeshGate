# ADR-001: Избор на MQTT брокер — EMQX 5.8.x зад неутрален adapter интерфейс

- Статус: Прието (по подразбиране, без изричен отговор от собственика — преразглежда се лесно)
- Дата: 2026-10-12
- Влиза в сила: Фаза 0 имплементация

## Контекст

MeshGate изисква брокер с: управление през API (клиенти, теми, ACL, статистика),
per-device MQTT креденшъли, TLS listeners и възможност за bridge. Платформата се
планира като отворен (разпространяем) продукт, затова лицензът на брокера е
критерий от първи ред. Изрично изискване в спецификацията: точна версия, издание и
лиценз да са проверени преди имплементация.

## Проверени факти (октомври 2026)

- EMQX до **5.8.x** включително е под **Apache 2.0** (последна свободна линия; търсеният
  таг е 5.8.8 — потвърждава се при първи `docker pull` преди фиксиране).
- От **5.9.0 (май 2025)** EMQX преминава на **BSL 1.1** (изданията са слети); всяка версия
  става Apache 2.0 четири години след релийвър. v6.x също е BSL. BSL позволява собствена
  употреба, но пречи на разпространение като отворен продукт.
- EMQX 5.x има Management REST API v5 (клиенти, subscription-и, publish, статистика,
  listeners, authn/authz/built-in database) — достъпно в 5.8 линията.
- EMQX няма native Windows поддръжка — локално върви само в Docker.

## Алтернативи

| Опция | Лиценз | Защо не (сега) |
|-------|--------|----------------|
| EMQX 6.x | BSL 1.1 | блокира отвореното разпространение на продукта |
| Eclipse Mosquitto | EPL 2.0/EDL | лек и доказан, но администрацията е файлово-базирана — трябваше собствена логика за ACL/динамика, точно каквото избягваме |
| NanoMQ | MIT | edge-ориентиран, по-беден management API |
| собствен mqbroker (mqtt-server/) | наш | на M0: QoS 0, без auth/ACL/bridge/retain — не покрива приемъчните тестове за сигурност; бъдещ driver, не пръв backend |

## Решение

1. Основен брокер: **EMQX 5.8.x** (фиксиран таг, без `latest`), Apache 2.0.
2. Core API говори с брокера през **неутрален `BrokerAdapter` интерфейс**:
   `status()`, `list_clients()`, `list_subscriptions()`, `list_topics()`,
   `upsert_device_credentials()`, `statistics()`, `publish()` (+ ACL операции).
   Първа имплементация: `EmqxAdapter` (REST API v5).
3. mqbroker (mqtt-server/) може да се добави като втори driver по-късно — интерфейсът
   не предполага EMQX-специфика извън adapter класа; решението за унифициран продукт
   остава открито и не блокира MVP.

## Последствия

- (+) Пълен management API веднага → приемъчният checklist (ACL, неоторизиран publish,
  статус на клиенти) е постижим във Фаза 1.
- (+) Apache 2.0 → продуктът може да се разпространява отворено с лицензена таблица.
- (−) 5.8.x линията не получава нови функции/поддръжка като 6.x; рискът се приема,
  защото broker-ът е заменяем чрез adapter-а (свързано: бъдещ ADR при смяна).
- (−) Задължителен Docker за локална работа (липса на native Windows).
- (!) При бъдеща смяна на брокер: нов ADR + миграция на ACL/креденшъли — интерфейсът
  вече предвиждa това.
