# ADR-008 — Карта 2.0: Мъгла и следи (Т34) + Плейбек и geofence (Т35)

Дата: 2026-10-31 · Статус: приет · Решава: собственикът („давай да се довършат“)

## Т34 — Мъгла и следи

1. **Мъгла = кофична плътност по позиционни events.** Клетка =
   правоъгълник `step`° (по подразбиране 0.02° ≈ 2 km; параметър в заявката).
   Бекендът връща САМО осветените клетки (count, last_ts, nodes, snr_avg);
   „никога не чувано“ (черно) се рендира клиентски като фон на viewport-а —
   нула данни за празните клетки по конструкция.
2. **Състояния на клетка (избледняване):** `live` (последен пакет < 1 ч) —
   ярко; `memory` (в прозореца, по-старо) — избледняващо сиво; извън
   данните — черно. Праговете са константи в UI (легендата ги описва).
3. **Фантоми:** възли от NeighborInfo ребра без позиция — ИЗВЕСТНИ вече от
   Т10 (Схема режим ги показва честно). Новото: брояч + списък в панела
   на Картата (клиентски, от същите данни — нула нови endpoints).

## Т35 — Плейбек + geofence

1. **Плейбек:** `GET /v1/devices/positions?hours=` — хронология на
   позиционни events (node, lat, lng, snr, ts; кап 4000). Плейбекът е
   GEO-режим: слайдер + play; всеки възел се рендерира на последната си
   позиция ≤ T; етикет показва T. Схема режимът е топология „сега“ — без
   време, честно.
2. **Geofence:** зони в settings `geofence`:
   `[{"name","node" ("*" = всички),"lat","lng","radius_m"}]` — System →
   „Геозони“ (GET/PUT /v1/system/geofence, admin+audit). На картата кръгове.
3. **Детектор:** `detect_geofence(rows, zones)` — чиста функция
   (haversine_m). „Напусна зоната“ = последната позиция ИЗВЪН радиуса И
   има позиция вътре в прозореца. Event kind `geofence`, severity
   `important`, key `geofence:<зона>:<възел>` — минава през съществуващия
   критичен цикъл (ack/silence/notify/тихи часове) без нови механизми.
4. **PKI/точност:** позиция без числови lat/lng се прескача; изчислението
   е haversine (добро до ~0.5% за км-радиуси — достатъчно за аларма).

## Последици

- Едно ново зависимо-свободно SQL (агрегация по клетка) + едно за хронология;
  критичният цикъл получава 4-ти детектор по познатия модел.
- UI: тоггъл „Мъгла“, тоггъл „Плейбек“ (слайдер), кръгове на зоните,
  „Геозони“ панел в System, 📍 ред в CriticalPanel/аларми.
- Производителност: агрегацията е по events за прозореца (индексирана по ts),
  cap 4000 реда за плейбек — реалната BG история е в този мащаб.
