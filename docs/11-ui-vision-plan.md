# MeshGate — план за интерфейса по визията от MeshGate.docx (docs/concept/)

Собственикът е категоричен: визията и ~90% от функционалностите са описани в
концептуалния документ (4-зонов редактор с palette/canvas/properties/test,
навигация с 8 секции, 6 типа блокове). Този документ мапва КЪМ НЕЯ — кое
съществува, кое идва, в какъв ред. Backend-ът и стекът са готови; работата е
предимно по фронтенда.

## 1. Целева навигация (дърво) — 8-те секции от документа

| Секция (по документа) | Днес в MeshGate | Какво липсва |
|---|---|---|
| **Dashboard** | Overview | уелком карти + статус на секциите |
| **Monitoring** | Мониторинг (графики) + Packet Explorer + Devices & Mesh | телеметрия графики per възел, топология, карта (с 3a/3b) |
| **MQTT Brokers** | MQTT Broker (listeners/клиенти/абонаменти/тест) + локален статус | външни брокери като източници (inbound, R2) |
| **Bridges** | Bridges & Routes (CRUD, health, dry-run) | нищо съществено — ping статистика (R2) |
| **Routing Rules** | Routing Rules: Помощник + wizard + шаблони + версии + журнал | **визуалният канвас редактор (R3)** |
| **Automation** | — (никаква — правилото е без празни страници) | известия/действия (Фаза 5): THEN-блокове, Node-RED |
| **Integrations** | — | Meshtastic/MeshCore настройки + статус (3a), HA/n8n (Фаза 5) |
| **Security & Settings** | System & Security (потребители, audit) + Profiles | сегмент: настройки на брокера в UI |

Промяната на навигацията е евтина и става с всяка фаза — секция се появява,
когато зад нея има реален екран (без placeholders). „План & Тестове" оставя
като собствена малка секция (по изрично желание на собственика).

## 2. Визуалният редактор (4-зоновата визия) — на части

Дизайн-референциите (docs/concept/media) са EMQX Flows / n8n / React Flow
стил: лява palette с блокове, централен канвас с връзки, дясно properties,
долу Test панел. Реализация на 3 стъпки, всяка носи стойност сама:

- **R3.1 — Read-only визуализация (1 сесия):** всяко правило се РЕНДРИ като
  блок-диаграма (Source → Filters → Transform → Destinations) от същия JSON
  модел — чист SVG, без нови зависимости; входът остава wizard/Помощник.
  Ефект: собственикът вижда правилото като диаграма веднага.
- **R3.2 — Интерактивен канвас (React Flow, ADR):** drag-drop на блоковете от
  palette, свойства вдясно, Test панел долу (dry-run trace). Компилира до
  СЪЩИЯ JSON (единствен източник на истината) — wizard/Помощникът остават
  бързият път за прости правила.
- **R3.3 — Router/Branch блок + много изходи** (P1 от документа): условни
  разклонения, импорт/експорт на flows като JSON.

## 3. Описателност към оператора (по бележките на собственика)

- Всеки екран обяснява какво показва с едно изречение под заглавието
  (започнато в Мониторинг/План — довършва се навсякъде).
- Packet Explorer: колона „разпознато като" (Meshtastic TEXT/POSITION/…,
  generic JSON, текст, бинарно) след 3a.
- Демо нодовете (въпрос на собственика): днес генерират опростен JSON
  (телеметрия/позиция/съобщение/частно) върху `mesh/emul/…` — НЕ реалния
  Meshtastic формат. С емулатор v2 (docs/10 §3.5) минават на
  Meshtastic-подобни теми/payload и всеки пакет ще носи разпознат тип.
- First-run съветник (имплементиран): при първо влизане с началната парола —
  смяна на парола + кратка разходка из секциите.

## 4. Ред на изпълнение (кое кога)

1. **Сега (2.5, готово):** Помощник, Мониторинг, План & Тестове, first-run
   съветник, описателни подзаглавия.
2. **Фаза 3a — Meshtastic на живо:** детектор + JSON декодер + емулатор v2 +
   реални канали в Помощника (docs/10). Изпълнително условие: собственикът
   закича публичен брокер и вижда разпознати съобщения.
3. **R3.1** — read-only диаграма на правилата (визията става видима).
4. **R2** — inbound мостове (два публични брокера за тест), retry/dead-letter,
   метрики per rule, webhook destination.
5. **R3.2/3.3** — пълният канвас редактор + Router/Branch.
6. **Фаза 5/6** — Automation (известия), Integrations, MeshCore.
