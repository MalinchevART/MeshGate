# Креативна изследователска вълна + UI redesign (docs/14)

Задание от собственика (2026-10-22): СЛЕД редовно планираните задачи —
дълбоко планиране и проектиране на две посоки: (A) паралелно изследване на
нета за подобни проекти и креативни нови функции с рейтинг ≥9/10; (B) цялостен
redesign на интерфейса (сегашният е „функционален но семпъл като страница на
първокурсник").

## Качествената граница (винаги важи)

Ако мислиш, че резултатът е добър — не е: най-добрият случай е 4/6.
Цикъл за всяка функция/дизайн решение:

```
Вариант 1 (~30 мин) → още 2 варианта → избери 2 от 3 → съчетай
→ върни се, прегледай, пипни пак → чак сега може „отличен"
```

## A. Изследователска вълна — паралелни прегледи

Един спринт, 4 паралелни прегледа + 1 синтезиращ:

| Направление | Обхват | Какво търси |
|---|---|---|
| 1 | Meshtastic екосистема | meshmonitor (liamcottle), Meshtastic web client, mqtt map проекти, AtakPlus/meshtastic-atak — какво показват, какви аларми/карти/топология |
| 2 | LoRa/IoT платформи | The Things Stack (LoRaWAN) UI, ChirpStack, TTN console — device management, data flows, живи графики |
| 3 | Мониторинг/дашборд култура | Grafana/Netdata/Zabbix UX патерни — как показват метрики, инциденти,健康 на мрежа |
| 4 | Диви идеи от съседни домейни | flight radar / marine AIS карти, SDR спектри, APRS.fi, радио-любителски инструменти, игри (fog of war карти), MIT scratch-style automation |

Синтезиращият преглед сравнява: (какво имат те) × (какво MeshGate няма) →
таблица Въведи по-добре / Измисли ново / Не ни трябва. Всяка избранa функция
минава през цикъла 3-варианта горе и през ADR (docs/07 методата).

### Кандидат-посоки за „ново, невиждано" (начални хипотези за надграждане)
- **RF„магла" карта**: SNR topология като топлинна мъгла върху картата, не
  само линии — мрежата „диша" в реално време (fog-of-war: непокрити зони).
- **Мрежов пулс**: една анимация, която показва health на цялата mesh мрежа
  като сърцебиене (възли = клетки, връзки = капиляри).
- **Симулатор „какво ако"**: плъзгач мощност/позиция на виртуален възел →
  предсказание кои връзки ще се появят/загубят (от натрупаните SNR данни).
- **Автогрупиране по RF**: клъстери на възлите по реален SNR, не по канал —
  „истинските съседства" в мрежата.
- **Месhtastic → белжик**: история на пакет по карта с анимация на пътя
  (от hop trace данните).

## B. UI redesign

### Фаза B1 — дизайн-основа (промпт за генериране отвън)

Собственикът иска опция да генерира дизайн-основа вън (Midjourney/Figma AI/
друг асистент). Готов промпт — копирай дословно:

```
Дизайн на уеб приложение за мониторинг и управление на Meshtastic LoRa mesh
мрежа (име: MeshGate). Тъмен професионален интерфейс за операторски център:
не терминал-ретро, а модерен NOC/SOC стил (мисли Bloomberg/Grafana/flight-
radar, не admin template).

Съдържание: ляво меню с 9 секции (Dashboard, Мониторинг, Устройства и мрежа,
Packet Explorer, Карта на възлите, Брокер, Мостове, Правила за рутиране,
Известия, Интеграции, Система и сигурност, План); топ лента с потребител;
основна зона с плъзгащи се панели и карти. Данни на живо: карта с възли и
RF връзки по SNR (зелено/оранжево/червено), графики на трафик, списък
пакети с цветни типове, блокови диаграми на правила за рутиране (източник →
условия → дестинации), батерии с цветова скала, топология „кой кого чу".

Изисквания: висока плътност на информация без претоварване; моно шрифт за
данни (node id, теми); статус цветове — тюркоаз акцент, зелено/жълто/
червено за здраве; анимации само със смисъл (пулс на живите данни); 1280×
 desktop + tablet; light/dark с тъмното по подразбиране; усещане за
"мрежата е жива". Дай design tokens (палитра, типография, spacing),
компоненти (card, panel, table, chip, modal, sidebar) и layout wireframes
на 3 ключови екрана: Dashboard, Карта, Правила за рутиране (с блочен
редактор-канвас).
```

### Фаза B2 — внедряване (собствени сили, по вариантите)

1. Три варианта на design tokens (патрит от B1 + собствен анализ) →
   съчетай двата най-добри → дизайн спецификация docs/15-design-spec.md;
2. Инфраструктура: CSS променливи вече има — минаваме на пълна token
   система (цвят/типография/spacing/elevation/състояния), един
   styles.css → слойна структура;
3. Компонентно потвърждение: таблиците → по-плътни с hover редове,
   chip/tag → единни, бутони → йерархия primary/ghost/danger, модали →
   консистентни, notification pattern;
4. Три ключови екрана по вариантния цикъл: Dashboard (герой: мрежовият
   пулс + карта мини), Карта (RF магла + по-богат избор на възел),
   Routing канвас (по-фини блокове + визуален feedback при dry-run);
5. Всяка стъпка със screenshot преди/след + тестовете остават зелени
   (никаква функционална промяна в B — само визия).

### Фаза B3 — полиране

Икони (едиен сет), празни състояния с обяснение, loading skeleton-и,
микроанимации при обновяване на живи данни, keyboard navigation.

## Ред на изпълнение

1. Редовно планирано: тест с реални възли (собственикът), Node-RED/ntfy
  изация през HTTP дестинацията (документация), Grafana/Influx по желание;
2. Спринт A (изследователска вълна) — паралелни прегледи + синтез;
3. Спринт B1/B2/B3 (redesign);
4. Функциите от A се внедряват в новия дизайн (не дважы).
