# Каталог с интеграции за MeshGate (docs/13)

Какво още може да се закачи към платформата и как. Подредени по лесно → трудно.
Вратите, които платформата вече има (docs/08-external-integration.md):

1. **MQTT вход/изход** — EMQX слуша `#`; Bridges (входящи/изходящи към външни
   брокери) + Routing Rules (канал → канал/брокър, с дедуп и защити).
2. **HTTP API** (`/v1/*`, сесии + RBAC) — packets, devices, map, topology,
   facets, stats; WebSocket стрийм `/v1/packets/ws`.
3. **Webhook изход** в Известията (JSON POST с валидация на URL).
4. **Креденшъли за брокер** — динамични потребители за EMQX с ACL по теми.

## Каталог

### 1. Home Assistant (най-исканата за дома)
- **Какво дава:** възлите като сензори в HA (батерия/SNR/позиция/последно
  съобщение), аларми от правилата като event, карта с локации.
- **Как се закача:** HA MQTT интеграция сочи към нашия EMQX (порт 1883,
  креденшъл от Брокер страница). Ние публикуваме `homeassistant/` discovery
  теми от правилата, или HA слуша `msh/#` през bridge topic_map.
- **Трудност:** лесна за четене (HA абонира), средна за discovery (правило,
  което публикува config съобщения). RBAC: отделен потребител с ACL само
  `homeassistant/#` + `msh/#` read.

### 2. Node-RED / n8n (визуална автоматизация)
- **Какво дава:** flow-ове върху реалните пакети — dashboards, филтри,
  съхранение, сложни условни автоматизации без код.
- **Как се закача:** mqtt-in node → нашия EMQX (креденшъл с ACL); или
  webhook от Известията към n8n.
- **Трудност:** лесна — стандартен MQTT клиент.

### 3. ntfy / Shoutrrr / uptime-kuma (push известия без Telegram)
- **Какво дава:** телефонски push без бот; heartbeat мониторинг на самата
  платформа.
- **Как се закача:** webhook канал в Известията към `https://ntfy.sh/<topic>`
  (или собствен ntfy). Uptime-kuma push монитор върху `/v1/system/health`.
- **Трудност:** лесна — работи със съществащия webhook канал.

### 4. Grafana / InfluxDB / Prometheus (история и графики)
- **Какво дава:** дълга история по SNR/батерия/трафик на възел, алармиране
  от Grafana, dashboards за RF здраве на мрежата.
- **Как се закача:** Telegraf mqtt_consumer върху EMQX → InfluxDB;
  Grafana чете Influx/Prometheus. Или експортен endpoint `/v1/metrics`
  (бъдеща малка задача — prometheus_client).
- **Трудност:** средна (външен стек, но без наш код с Telegraf).

### 5. Zigbee2MQTT (домашни сензори ↔ mesh)
- **Какво дава:** сензори у дома (температура/врата) да се пращат към mesh
  канал, и mesh съобщения да идват в домашната автоматизация.
- **Как се закача:** Zigbee2MQTT публикува в собствения си EMQX акаунт;
  Routing Rules превежда `zigbee2mqtt/<sensor>` → `msh/<регион>/2/e/<канал>/!…`
  и обратно (трансформации {payload.x} вече ги има).
- **Трудност:** средна — правила + форматни трансформации.

### 6. WhatsApp (фаза 5 продължение)
- **Какво дава:** аларми/съобщения в WhatsApp на собственика.
- **Как се закача:** Meta WhatsApp Cloud API (нужен business акаунт,
  токен, template съобщения) като нов тип канал в notification_channels;
  алтернатива — външен gateway (whatsapp-web.js) през webhook.
- **Трудност:** средна (Cloud API) / лесна (webhook gateway).
- **Статус:** планирано в docs/12 — канали + шаблони по канал.

### 7. APRS-IS (радио-аматьорска карта)
- **Какво дава:** възлите с позиция се виждат на aprs.fi; мост mesh ↔ HAM
  свят.
- **Как се закача:** малък worker: чете decoded позиции, праща TCP APRS
  feed (callsign + passcode на собственика). Правило излъчва към
  `aprs/<callsign>` темa, worker-я я превежда.
- **Трудност:** средна; нужнен ham callsign.

### 8. Matrix / XMPP (чат мостове)
- **Какво дава:** каналите (LongFast, Самоков…) като чат-стаи; отговори от
  телефона се връщат в mesh канала.
- **Как се закача:** matbridge/appservice слуша EMQX тема и Matrix; или
  ethlo-it/matrix-mqtt мост; нашата страна е само Routing Rules в двете
  посоки с mg_origin защита.
- **Трудност:** средна/трудна (външен компонент с потребители).

### 9. Meshtastic → интернет на неща (Tasmota/ESPHome)
- **Какво дава:** ESP устройства у дома да четат/пишат в mesh канали
  (напр. реле, командвано от mesh съобщение).
- **Как се закача:** Tasmota/ESPHome MQTT се насочват към EMQX с ACL
  тема; правила превръщат текстови команди в действия (или директно
  `cmnd/…` теми). Внимание: ACL по устройство, не `#`.
- **Трудност:** средна — по сценарий.

### 10. Собствен мобилен изглед / PWA (без инсталация)
- **Какво дава:** телефона като монитор (карта, батерии, аларми) през
  браузър с икона на началния екран.
- **Как се закача:** PWA manifest + service worker върху сегашния React
  (без нов backend); push през ntfy/webhook.
- **Трудност:** лесна/средна — фронтенд задача.

## Предложен ред (спрямо визията на собственика)

1. **Home Assistant** (домашна автоматизация + аларми) — най-полезна бърза
   победа; нужни са само discovery правила + креденшъл.
2. **ntfy push** (5 минути със съществуващия webhook канал).
3. **Node-RED** — демонстрира платформата като суровина за автоматизация.
4. **InfluxDB/Grafana** — RF история за тестовете с реалните възли.
5. **WhatsApp / Matrix / APRS** — по желание, по-късно.

Всички използват същите четири врати горе — няма нова архитектура, само
адаптери и правила.
