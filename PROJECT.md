# MeshGate — карта на проекта

**Какво е:** самостоятелна платформа за MQTT gateway, mesh мониторинг,
контролирани мостове и автоматизация — строена върху живата българска
Meshtastic мрежа. **Директория: `C:\Users\niki5\MeshGateProject\MQTT\meshgate`**
(стекът е жив на http://localhost/ — вход admin, паролата в `deploy/.env`).

## ПРЕДАВАНЕ

**Документът за предаване е `docs/17-handover.md`** (какво е готово,

уроци) → docs/17 → docs/16 (планът, всичко ГОТОВО) → docs/adr/.

## Идеята / концепцията

Meshtastic възлите (LoRa радиа) говорят през MQTT. MeshGate ги **слуша,
декодира, показва и управлява**: кой къде е, кой кого чува, кой мълчи,
кой има батерия — и позволява правила „ако X → препрати към Y" с
retry/dead-letter, известия (Telegram/имейл/webhook/WhatsApp), Home
Assistant. Целевият потребител е **операторът-човек**: името на възела е
главното, ID-то е второстепенно; топла палитра (не студено синьо);
нищо „mock като live".

## Архитектура (накратко)

- `apps/api/` — FastAPI + PostgreSQL: ingest (MQTT → базата, декодери
  JSON + бинарен protobuf), routing engine (правила, retry, dead-letter,
  backpressure), критични събития (фонов evaluator), известия, HA.
- `apps/web/` — React+TS (Vite, без нови npm зависимости): дизайн-система
  от токени (`styles.css` §1), компоненти (`components/ui.tsx`, Table),
  страници в `pages/`.
- `deploy/` — Docker Compose (emqx/postgres/traefik/web/api/emulator),
  инсталатор, меню, backup. **Фиксирани версии; никакъв latest.**
- `docs/01…16` — архитектура, API, планове. **`docs/16` е АКТИВНИЯТ план.**
- `docs/design/` — **дизайните** (концепт-арт от собственика, вариантни
  скици t1…t8, review-2026-10-24.md с функционалната карта F1–F22).
- Тестове: 118 unit + 52 integration (`docker compose exec api pytest …`).

## Как работим (правила)

1. Всяка точка = една фаза: 3 варианта → съчетай 2 → детайлни прегледи →
   QA+бъг-ловец PASS (скил `phase-execution`; при лимит на паралелни прегледи — водещият).
2. Контракти преди код (ADR в `docs/adr/`); нула нови npm зависимости без
   решение; миграции 001…011+ последователно; тестове за нов endpoints.
3. Край на сесия: обнови „Статус" в `AGENTS.md` + commit (там е детайлната
   дневна история — този файл е картата, не журналът).
4. Собственикът решава точка по точка; демо данни винаги маркирани.
